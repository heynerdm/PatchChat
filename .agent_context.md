# Contexto del Proyecto: PredictPath

## 1. Propósito General del Sistema
Sistema de análisis histopatológico multimodal asistido por IA. Recibe parches de imágenes histopatológicas, los codifica visualmente con PLIP, proyecta los embeddings al espacio de Llama-3-8B mediante una capa de proyección entrenada, y genera reportes patológicos estructurados (análisis morfológico, diagnóstico clínico, identificación de estructuras y reportes formales).

## 2. Arquitectura y Stack Tecnológico
- **Modelo Visual (Encoder):** PLIP (`vinid/plip`) — genera embeddings de 768-dim desde parches histopatológicos
- **Capa de Proyección:** MLP custom `PLIPToLlamaProjector` (768→4096, ~6.4M params) — GELU + LayerNorm + Linear
- **Modelo de Lenguaje:** Llama-3-8B (`HeynerMarqu/pathology_llama3_completo`) — cuantizado en 4-bit (NF4, BitsAndBytes)
- **Servidor de Inferencia:** FastAPI + Uvicorn, expuesto vía Ngrok desde Kaggle (GPU T4)
- **Frontend / Interfaz:** Streamlit (`chat_pathology_v2.py`)
- **Entrenamiento:** PyTorch, ejecutado en Kaggle con GPU T4 x2
- **Base de Datos / Almacenamiento:** `embeddings_benchmark.json` (~154 MB) — diccionario hash_MD5 → {filename, embedding[768], metadata_clinica}. Pesos del clasificador en `Pesos/`. Pesos LoRA en `Pesos/pathology_lora_weights/`

### Flujo de datos clave
```
[Usuario sube imagen PNG/JPG]
        │
        ▼
[Streamlit: chat_pathology_v2.py]
        │
        ├─ Calcula hash MD5 del archivo
        ├─ Busca match en embeddings_benchmark.json
        │   ├─ Match → extrae metadata_clinica + embedding pre-computado
        │   └─ No match → marca como "imagen externa"
        │
        ├─ Construye prompt (contexto clínico + tarea de análisis)
        │
        ▼
[POST /generate → Servidor Kaggle vía Ngrok]
        │
        ▼
[kaggle_inference_server.py]
        ├─ PLIP:       imagen → embedding [1, 768]
        ├─ Proyector:  [1, 768] → visual_token [1, 1, 4096]
        ├─ Llama-3:    embed_tokens(prompt) → text_embeddings [1, seq, 4096]
        ├─ Concat:     [visual_token ‖ text_embeddings] → [1, 1+seq, 4096]
        └─ Generate:   → texto generado (reporte patológico)
```

### Endpoints del Servidor (kaggle_inference_server.py)
| Método | Ruta       | Descripción                        |
|--------|------------|------------------------------------|
| GET    | `/health`  | Estado del servidor y modelos      |
| POST   | `/analyze` | Recibe `image_b64` + `prompt`, retorna análisis |

## ⚡ Próxima Dirección: Arquitectura Fiel a PathAgent (Trident + CONCH + Llama-3)
> **Directiva de diseño:** Replicar con máximo rigor científico la arquitectura del paper **PathAgent** para garantizar análisis histopatológicos precisos y trazables, introduciendo como aporte diferencial nuestro modelo **Llama-3-8B** como Executor central.

### Stack Tecnológico Oficial del Pipeline:
1. **Preprocesamiento WSI:** **Trident** (Harvard Mahmood Lab) para estandarización de lectura, segmentación de tejido y cálculo de cuadrículas de parches a multirresolución ($5\times$, $10\times$, $20\times$).
2. **Navigator / Patch Encoder:** **CONCH** (`MahmoodLab/CONCH` o `conch_v15` de Harvard / PLIP como alternativa directa) para extracción de embeddings visuales de alta precisión diagnóstica y cálculo de similitud con la consulta clínica.
3. **Perceptor:** Generación de descriptores morfológicos para los parches clave seleccionados.
4. **Executor (Razonamiento Agéntico):** **Llama-3-8B** (`HeynerMarqu/pathology_llama3_completo`), operando como el orquestador central con Multi-Step Reasoning (predicción preliminar $\to$ auto-reflexión de suficiencia $\to$ solicitud de zoom dinámico en coordenadas $X,Y$ $\to$ síntesis de reporte final con Chain-of-Thought).

## 5. Restricciones y Reglas del Proyecto
- **Entorno de ejecución 100% ONLINE EN KAGGLE (CRÍTICO):** Todo el procesamiento pesado (WSI ingesta con Trident, segmentación de tejido, extracción y filtrado de parches con CONCH Navigator, y razonamiento de Llama-3-8B Executor) se ejecutará **online en Kaggle** con aceleración GPU (T4 / P100 / dual T4). La máquina local no procesará gigapíxeles ni cargará modelos pesados; solo actuará como frontend liviano (Streamlit) conectado vía túnel Ngrok.
- **Acceso a Modelos en Hugging Face:** Se requiere configurar el Kaggle Secret `HF_TOKEN` con permisos para:
  - `HeynerMarqu/pathology_llama3_completo` (modelo Llama-3 privado).
  - `MahmoodLab/CONCH` / `MahmoodLab/conchv1_5` (gated repository de Harvard).
- **WSI Dataset Oficial en Kaggle:** Se utiliza el dataset **`tcga-brca-diagnostic-slide-17`** (40 láminas `.svs` de diagnóstico de TCGA-BRCA).
  - Ruta verificada por el usuario: `/kaggle/input/datasets/aryaze/tcga-brca-diagnostic-slide-17/016fc18e-1a88-478f-82a4-38f4f10a8f42.svs`
  - Carpeta base de láminas: `/kaggle/input/datasets/aryaze/tcga-brca-diagnostic-slide-17/`
- **Dependencia de Ngrok:** Cada sesión de Kaggle genera una URL de Ngrok nueva — debe pegarse manualmente en el sidebar de Streamlit.
- **Cuantización obligatoria:** Llama-3-8B siempre se carga en 4-bit NF4 para caber en la GPU T4 de Kaggle (~16 GB VRAM) junto a los módulos de visión.
- **Idioma:** La interfaz y los prompts están en español. Las respuestas del modelo pueden ser en español o inglés según el prompt.
